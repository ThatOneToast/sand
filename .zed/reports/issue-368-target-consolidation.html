Issue #368: one target model, one authoring path

Sand’s selector, target, and query ladder has been consolidated behind Target. Category and cardinality remain statically enforced, while command use, filtering, iteration, and scoreboard conversion now share the same discoverable model.

The removed surface is not merely renamed. The entity/player target wrappers, their aliases, the query wrappers, the damage conversion trait, and command-local predicate/tag/team identifier wrappers were deleted. Only the low-level selector IR remains hidden behind Target.

Canonical architecture

Construct & filterTarget::entities(), players(), tags, scalar ranges, score pairs, canonical predicate IDs
→
Order, narrow, or iterate.sort(...) preserves many; .nearest() encodes one; .each(...) binds an EntityContext
→
Consume directlyCommands, execute chains, storage, VFX, participants, and score holders
let enemy = Target::entities()
    .entity_type(EntityType::Zombie)
    .tag("enemy")
    .within_blocks(16.0)
    .nearest();

cmd::damage(enemy, 4.0);
  • Hidden type state: category (AnyTarget/PlayersOnly) and cardinality (One/Many) are inferred, preserving compile-time constraints without adding author vocabulary.
  • Capability boundaries: player-only filters exist only on player targets; single-target commands accept only statically single targets.
  • Execution stays honest: TargetExecution adds state/each to the same target value, while EntityContext remains the distinct bound-executor concept.
  • Raw assertions stay complete: raw_single preserves single cardinality through ScoreHolder, while raw_single_player additionally preserves the player-only category for commands and iteration. Fake players and wildcard holders remain separate scoreboard concepts with centralized validation.
  • Named filters stay observable: an unfiltered named target remains the literal player token, while adding filters lowers it to @a[name=<player>,...,limit=1] so filters cannot disappear and cardinality remains one.
  • No selector-era helper vocabulary: typed level bounds are scalar methods, multiple score filters are ordinary (ObjectiveName, ScoreRange) pairs, and raw syntax is explicitly named _raw.

Semantic boundaries retained

Consolidation is based on meaning, not on whether two values eventually render text. These types remain separate because they model different operations or data:

TypeWhy it is not another Target
EntityContext<K>The currently bound @s executor inside generated code, not an expression that selects entities. The redundant PlayerContext alias was removed; player context is EntityContext<PlayerKind>.
StateQueryComposes required, optional, and forbidden component presence. Its lowering uses the canonical target machinery, but the query itself is not a selector.
RelationTraversalA pending vanilla execute on <relation> traversal. Renaming it from RelationQuery makes that distinction explicit.
ScoreHolderA strict superset of entity targets that must also represent fake players and wildcard *.
Predicate JSON structsEntityPredicate, ItemPredicate, location, damage, and weather predicates are different vanilla JSON schemas—not aliases for one selectable value.
The facade audit also removed unused compatibility aliases Identifier, Rarity, and Slot. Canonical names are ResourceLocation, ItemRarity, and ItemSlot.
