2026-11-05 · Sand framework cleanup and independent authoring experiment

A broad datapack is discoverable—but workflow examples and native validation matter

Base 6d309e27 + local implementation · fresh agent used a frozen 11,625-entry CLI catalog

Outcome

A fresh agent built Vanilla Expedition using only sand api to learn Sand. Its 96-component export connects progression, combat rewards, dialogs, custom items, recipes, loot, effects and presentation, with dimension, worldgen and enchantment resource samples. It used no handwritten raw commands, JSON or SNBT. The original pack compiled but failed native loading. The repaired pack now passes Minecraft 26.3 startup, reload and shutdown.

The experiment was useful because it found concrete product defects, not just missing documentation. Those findings drove search/navigation fixes, a reachable score-read type, complete State and Scene examples, missing-registration diagnostics, corrected dialog dismissal, and target-specific advancement validation.

Independent baseline assessment

The agent rated discoverability 5/10, composability 7/10, diagnostics 7/10, and representative export breadth 8/10. These are subjective ratings from one authoring attempt, not percentages of vanilla support. They describe the frozen baseline, not the repaired CLI.

The strongest positive result was breadth: typed authoring reached many different resource families without raw escape hatches. The weakest experience was finding a complete workflow from isolated signatures. The agent frequently needed compiler diagnostics or exported-file inspection to finish the connection between a declaration and its use.

Findings and repairs

API-01 · Fixed · discovery

Keyword matching confused “quest” with “requested”

The baseline query surfaced build-version fields because it matched identifier interiors. Search now matches word/identifier starts, including snake_case and CamelCase boundaries. A regression checks both useful quest results and exclusion of requested_version. The fresh query reaches gameplay and quest-related APIs instead of those version fields.

Evidence: sand-cli/src/api_cmd.rs; retained baseline search output and fixed-quest.json.gz.

API-02 · Fixed · navigation

Type discovery did not reliably lead to its own members

Source-authored contracts can place methods in a parent module. Querying Roster suggested unrelated systems, and module browsing did not consistently expose its methods. Type browsing now resolves aliases and groups direct member identities independently of their declared module. Show output points to the member query, with the constructor first in related APIs.

Regression covers human/JSON output and alias resolution. sand api module sand::systems::Roster now lists all nine methods.

API-03 · Fixed · public return type

A public getter returned a type that could not be discovered or named

EntityScoreAccessor::get already returned EntityScoreValue, but the façade did not export that existing type. The fix exposes the canonical type and its two existing methods, with contracts explaining that it represents a Minecraft read command rather than a Rust runtime value. All three API profile baselines were regenerated; no parallel wrapper was introduced.

The downstream example fixture now names the return type. State discovery also includes bound access, field constants, initialization and query usage.

API-04 · Fixed · alternatives

RawCopper was classified as an escape hatch

A broad ::raw name match treated ordinary registry variants as unsupported authoring boundaries. Classification now recognizes explicit raw method names and descriptive contract prose while excluding ordinary raw-material variants. Advice under “avoid when” no longer misclassifies the typed API that recommends an alternative.

EXPORT-01 · Fixed · correctness

An unregistered scene exported a dangling helper call

The agent independently found a successful build whose Scene start target was absent. The pipeline now rejects static missing references under the private owned-gameplay helper namespace, including recognized execute conditions, return chains, scheduled calls and macro command bodies. The diagnostic names the missing function and tells the author to register the definition.

External author functions remain allowed; unknown dynamic targets are not claimed as validated. Parser regressions distinguish executable references from quoted chat/comments. Scene discovery now includes registration and invocation together.

NATIVE-01 · Fixed · release-blocking output

Dialog dismissal used a nonexistent native action

The parent's native smoke test rejected minecraft:close. The jar's ActionButton codec has an optional action; dismissal now omits that payload. Regression checks the exact emitted button JSON. The broken native log and codec inspection are retained.

This defect was not exposed by the original compile/export checks. The repaired pack subsequently loaded and reloaded successfully.

NATIVE-02 · Fixed · export validation

A displayed root advancement lacked its required background

After dialog repair, Minecraft rejected the root advancement. Target-aware 26.3 export now requires a background for a root with display metadata and rejects backgrounds on children. The diagnostic points to AdvancementDisplay::background or assigning a parent. The retained replay project explicitly adds a vanilla stone texture.

The original author source is archived separately. Older/unversioned serialization is not silently presented as new native proof.

Repository cleanup and documentation

  • README rewritten around author goals, prerequisites, a reproducible project setup, local discovery, examples, iteration and explicit current limits.
  • Installation, agent CLI, dialogs, examples index, roster/progression evidence, capability matrix, contributor guidance and roadmap reconciled with current behavior.
  • The unused global StorageVar named as player data was removed from the starter template; it was an inappropriate first example for canonical player State.
  • scripts/validate_alpha.py provides one repository command for the two maintained alpha scenarios. It refuses existing output directories, retains logs, checks evidence rather than exit status alone, continues after one scenario fails and reports aggregate failure.

What remains

The alpha is still bounded work in progress. Actual player menu/sneak input, rendering, the full declared population under measured load, pack-wide reset/uninstall/upgrade policy, and general author-defined scenario tooling remain open. This turn did not implement a general sand test command or prove an operating envelope.

For CLI discovery, prioritize more complete construction/registration/use examples, conversion guidance and a broader signature-type reachability audit. The one missing score type was repaired; this is not a proof that every external generic or return type has perfect discovery. Low-level function-tag composition and canonical inventory navigation still deserve clearer guidance.

The breadth inventory explicitly leaves full worldgen, many cosmetic/data-driven resource families, complete loot/predicate semantics, overlays and numerous native signals unattempted or deferred. Finding a catalog entry does not establish its native correctness. No entire unattempted family was labeled unsupported.
