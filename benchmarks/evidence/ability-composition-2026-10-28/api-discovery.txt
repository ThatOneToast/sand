sand::systems::ability::Ability::accept
pub fn accept (& self , target : Condition , effects : impl IntoCommands) -> Actions

Recheck eligibility and target acceptance together, then commit once.

Context
  Recheck eligibility and target acceptance together, then commit once. The grouped branch is evaluated before cost/cooldown writes, so those writes cannot suppress later effects. Effects may be Actions or typed function calls. A native failure after acceptance leaves the committed cost and cooldown.

Minecraft behavior
  Uses canonical State writes and grouped Conditions in the ordinary export pipeline.

Parameters
  target (`Condition`): Acceptance condition for the current terminal target.
  effects (`impl IntoCommands`): Effects issued after payment, including typed function calls.

Returns
  `Actions` — One grouped acceptance branch with cost, cooldown and effects in order.

Use when
  - Composing shared resources and accepted-target abilities

Avoid when
  - Transactional rollback or asynchronous target ownership is required

Example
  use sand::prelude::*;

fn demonstrate(ability_value: &sand::systems::ability::Ability, target: sand::condition::Condition, effects: impl sand::component::IntoCommands)  {
    let accept = ability_value.accept(target, effects);
}
