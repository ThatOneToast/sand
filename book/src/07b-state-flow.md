# Derived State Transitions

Gameplay transitions are authored against fields generated by
`#[derive(State)]`. A transition function reads the bound State, updates its
typed fields, and calls other registered Sand functions through the canonical
function handle.

```rust,ignore
use sand::prelude::*;

#[derive(Clone, Copy, PartialEq, Eq, StateEnum)]
enum BossPhase { Fighting, Enraged, Defeated }

#[derive(State)]
#[state(namespace = "boss", scope = player)]
struct Combat {
    #[state(default = 100, min = 0, max = 100)]
    health: Score,
    #[state(default = "BossPhase::Fighting")]
    phase: EntityEnum<BossPhase>,
}

#[function]
fn enter_enraged() {
    cmd::tellraw(Target::self_(), Text::new("Enraged!").dark_red());
}

#[function]
fn update_boss() {
    let combat = Combat::on(EntityContext::<PlayerKind>::default());
    when(combat.health.lte(50)).then_all([
        combat.phase.set(BossPhase::Enraged),
        cmd::function(enter_enraged),
    ]);
}
```

For reusable behavior, put the function behind a typed System or event. For
reusable data composition, derive `StateBundle`; for presence filtering, derive
`StateQuery`. These all operate on the same State declarations and do not
introduce a parallel state-machine storage model.
