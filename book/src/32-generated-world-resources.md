# 32. Generated World Resources

Reference table for every resource a `sand.build.rs` script can produce,
badged consistently with the rest of this section.

| Resource | Path | Badge |
|---|---|---|
| Dimension definition | `data/<namespace>/dimension/<id>.json` | 🌍 World (datapack) |
| Generated world-init function | `data/<namespace>/function/__sand_world_init.mcfunction` | 🌍 World (datapack) |
| `minecraft:load` tag contribution | `data/minecraft/tags/function/load.json` (merged, not overwritten) | 🌍 World (datapack) |
| `server.properties` `view-distance`/`simulation-distance`/`difficulty`/`online-mode` | *(not a file in the datapack — see below)* | 🖥️ Server (host) |
| `dist/.sand-server-config.json` | Sibling of `dist/<namespace>/`, never inside it | 🖥️ Server (host) |
| World-reset behavior | `dist/server/world/` (deleted/regenerated by `sand run`, not a datapack file) | 🖥️ Server (host) |

## The generated `__sand_world_init` function

Spawn, world border, gamerules, time, and weather all lower into one
generated function, run once on datapack load via a `minecraft:load` tag
entry. For example, this `World`:

```rust
use sand::build::{Spawn, TimeConfig, World, WorldBorder};

let world = World::new()
    .spawn(Spawn::at(0, 100, 0))
    .border(WorldBorder::diameter(2000.0))
    .gamerule("keepInventory", "true")
    .time(TimeConfig::set(6000).frozen());
```

produces:

```mcfunction
setworldspawn 0 100 0 0
worldborder center 0 0
worldborder set 2000
worldborder damage amount 0.2
worldborder warning distance 5
worldborder warning time 15
gamerule keepInventory true
time set 6000
gamerule doDaylightCycle false
```

## Merging with your own `Load` hooks

If your project also has `#[function(Load)]`/`#[datapack_component(Load)]`
hooks (the ordinary, non-`sand.build.rs` way to run something on datapack
load), `sand-cli` **merges** the `minecraft:load` tag's `"values"` array
rather than one output overwriting the other. Both `sand_export` and
`sand_build_world` can legitimately want to add entries to the same vanilla
tag file, and both do.

## Validation

Before anything is written to disk, `SandBuild::validate()` runs a set of
structural checks and reports **every** failure at once (not just the
first), naming the offending builder call:

- **World border** — diameter must be in `(0, 59_999_968]` (vanilla's
  `WorldBorder#MAX_SIZE`); `damage_per_block` must not be negative.
- **Duplicate dimension slots** — the same `DimensionSlot` (e.g. two
  `Overworld` entries) configured twice.
- **Flat generator layers** — at least one layer required; each layer's
  height must be `> 0`; total layer height must not exceed the 384-block
  build-height limit.
- **Vanilla biome references** — a `minecraft:`-namespaced biome passed to
  `FlatGenerator::biome` or `NoiseGenerator::single_biome` must be a real
  vanilla biome ID (checked against a bundled list of vanilla's
  `worldgen/biome` registry contents). A custom mod/datapack namespace is
  never checked — Sand cannot know about registry content it didn't
  generate.

```console
$ sand build
sand.build.rs produced an invalid world configuration:
  - World::border: diameter 100000000 is out of range (0, 59999968]
  - Dimension[minecraft:overworld].generator: FlatGenerator has no layers — a flat world needs at least one
  - Dimension[minecraft:overworld].generator: FlatGenerator::biome 'minecraft:dessert' is not a known vanilla biome
```

**Scope note:** this combines structural/range checks with a bundled,
hand-maintained biome registry list — it is not a full audit against every
Minecraft worldgen registry (structures, noise settings, block references,
etc.) generated fresh per `VersionProfile` the way `sand-build`'s block/item
registries are, and it is not a real Minecraft server load the way
`sand-vanilla-audit` validates other datapack content. Extending Sand's
registry codegen pipeline to cover biomes/structures automatically, and/or
wiring world-build resources into a real-server `sand-vanilla-audit` pass,
are tracked follow-ups — see this feature's PR description for the linked
issue.

## Golden-file tests for generated output

`sand-core/tests/build_snapshots.rs` byte-for-byte compares generated
resources — flat, void, noise (vanilla and single-biome-override), and a
custom dimension slot/type, plus the world-init function and its
`minecraft:load` tag contribution — against fixtures under
`sand-core/tests/fixtures/build/`. Run
`UPDATE_SNAPSHOTS=1 cargo test -p sand-core --test build_snapshots` to
regenerate a fixture after a deliberate output-format change; review the
diff in the resulting fixture file the same way you'd review any other
generated-code change before committing it.
